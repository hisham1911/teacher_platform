# تشغيل أول Pilot للمعلمة

هذا الدليل يبدأ بعد نشر الواجهة والـAPI وإتمام إعدادات `docs/deployment.md`. لا توجد بيانات طلاب أو نتائج وهمية في Production.

## قبل دعوة المعلمة

1. تحقق من DNS وTLS و`/health/live` و`/health/ready`، ثم شغّل فحص النشر.
2. اختبر إرسال تأكيد البريد واستعادة كلمة المرور عبر SMTP الحقيقي.
3. اختبر رفع صورة/صوت وتنزيل شهادة عبر S3 الحقيقي، وثبّت قرار ترخيص QuestPDF والخط العربي.
4. فعّل backup المشفر ونسخته off-host ومؤقت المراقبة، ونفّذ تنبيهًا تجريبيًا.
5. أنشئ Platform Admin بالطريقة الموثقة، وفعّل الخطة المناسبة للمستأجر بعد إنشاء الـWorkspace.
6. اعتمد نصوص الخصوصية والشروط مع المستشار القانوني للجهة قبل توجيه مستخدمين حقيقيين إليها.

## حساب مريم وWorkspace الأول

1. أنشئ حساب مشغل حقيقيًا منفصلًا عبر `/auth/signup`، وأكد بريده عبر SMTP، ثم امنحه `PlatformAdmin` مرة واحدة بالطريقة الموجودة في `docs/deployment.md`. لا تستخدم حساب مريم كمدير عالمي.
2. تسجل مريم بنفسها عبر `/auth/signup` ببريدها الحقيقي، وتفتح رسالة التأكيد، ثم تسجل الدخول. غياب SMTP صالح Hard blocker لهذه الرحلة؛ لا تحدّث `EmailConfirmed` يدويًا.
3. تنشئ مريم Workspace من `/onboarding`. الإنشاء الحالي يجعل المستخدم المصادق عليه Owner داخل المعاملة نفسها؛ لا يلزم إدخال مستخدم أو عضوية مباشرة في قاعدة البيانات.
4. يدخل المشغل إلى `/platform`، ينشئ خطة pilot أو يختار خطة موجودة، ثم يفعّلها على Workspace مريم. يبقى هذا الإجراء منفصلًا عن عضوية Workspace.
5. لا تنشئ حسابات وهمية أو bypass للتأكيد. استخدم في smoke test مريم والمشغل الحقيقي فقط، والطالب Guest من نافذة متصفح منفصلة.

## رحلة المعلمة الأولى

1. تسجل من `/auth/signup`، تؤكد البريد، ثم تنشئ Workspace من شاشة onboarding.
2. ينشئ المشغل الاشتراك اليدوي من `/platform` إذا كان الـpilot يستخدم خطة محددة.
3. تنشئ المعلمة بنك أسئلة ثم سؤالين على الأقل، وتراجع المعاينة قبل النشر.
4. تنشئ Quiz، تضبط النجاح والوقت عند الحاجة، تضيف الأسئلة، ثم تنشره.
5. تنشئ استبانة مرتبطة بالاختبار وتنشرها إن كانت مطلوبة، وتراجع قالب الشهادة الافتراضي.
6. تنشئ Session من الاختبار المنشور وتفعّلها، ثم تشارك Join Code أو رابط اللاعب.
7. تستخدم متصفحًا منفصلًا كطالب تجريبي حقيقي: انضمام، إجابة، F5، إكمال، نتيجة، استبانة، وشهادة عند النجاح.
8. تعود كتطبيق معلمة إلى تقرير الجلسة، تراجع المحاولة وتحليل الأسئلة، وتنزّل CSV.
9. تختبر Session من نوع Live مرة واحدة: Lobby، فتح سؤال، إغلاقه، ظهور الترتيب، ثم الإنهاء.

## Smoke test إلزامي على Production

لا تعتبر النشر ناجحًا من health checks وحدها. نفّذ البنود التالية على رابط Production نفسه وسجّل Full SHA المنشور ووقت الفحص وأي `X-Request-Id` لفشل، من دون تسجيل tokens أو كلمات مرور.

### Teacher

- [ ] تسجيل الدخول بحساب مريم المؤكد، واختيار Workspace الصحيح.
- [ ] فتح بنك الأسئلة، وإنشاء سؤال فعلي مناسب للـpilot؛ اختبر رفع وسيط واحد إذا سيُستخدم في الـpilot.
- [ ] إنشاء Quiz، إضافة السؤال، ضبط نسبة النجاح، معاينة الاختبار، ثم نشره.
- [ ] إنشاء Session بنمط `SelfPaced` وتفعيلها ونسخ رابط اللاعب/Join Code.

### Student

- [ ] فتح الرابط العام ثم `/play/{joinCode}` في نافذة منفصلة، والانضمام باسم المشغل الحقيقي كطالب Guest.
- [ ] إرسال إجابة، ثم تنفيذ F5 والتأكد أن الاسم والمحاولة والسؤال تُستعاد من `GET /api/v1/player/sessions/{joinCode}/me` عبر Guest Cookie، لا بطلب DisplayName جديد.
- [ ] إكمال الأسئلة وإنهاء المحاولة وفتح النتيجة.

### Reports, survey, certificate, parent share

- [ ] فتح تقرير الجلسة كمعلمة ومطابقة المحاولة والدرجة وتحليل الأسئلة مع الإجابات المرسلة.
- [ ] تنزيل CSV وفتحه والتحقق من رؤوس الأعمدة والقيم والترميز.
- [ ] نشر Survey مرتبطة بالاختبار، ثم إكمالها من رحلة الطالب والتأكد من ظهور حالة الإرسال.
- [ ] تحقيق درجة نجاح، وطلب الشهادة، والانتظار حتى تصبح جاهزة، ثم تنزيل PDF وفتحه والتحقق من الخط العربي.
- [ ] إنشاء Parent Share وفتح `/result/{publicToken}` في نافذة بلا تسجيل دخول، والتأكد أن الرابط يعرض النتيجة المقصودة فقط.

### Live

- [ ] إنشاء Session بنمط `Live` وتفعيلها، وفتح شاشة المضيف `/dashboard/sessions/{sessionId}/live`.
- [ ] انضمام Guest من متصفح منفصل وظهوره في Lobby.
- [ ] بدء السؤال، إرسال الإجابة قبل الإغلاق، ثم إغلاق السؤال والتحقق من النتيجة/الترتيب.
- [ ] فتح السؤال التالي إن وُجد ثم إنهاء المسابقة، والتأكد من وصول المضيف والطالب إلى الحالة النهائية.

### Security وOperations

- [ ] HTTP يتحول إلى HTTPS، وشهادة TLS صالحة، والواجهة والـAPI وWebSocket تعمل بلا mixed content.
- [ ] `/health/live` و`/health/ready` يعيدان 200، وخدمتا backup وmonitor ومؤقتاهما ناجحة، وآخر backup مشفر موجود في الموقع المحلي وoff-host.
- [ ] كوكيز Production المسماة `__Host-tp-refresh` و`__Host-tp-guest` تحمل `HttpOnly`, و`Secure`, و`Path=/`، بلا `Domain`، وبقيمة SameSite المطابقة للإعداد المختار.
- [ ] لا تظهر أخطاء أو تحذيرات غير مفسرة في Console أو طلبات شبكة فاشلة أثناء الرحلتين Self-paced وLive.
- [ ] مستخدم حقيقي من Workspace آخر لا يستطيع قراءة أو تعديل موارد Workspace مريم؛ لا تستخدم PlatformAdmin لإثبات عزل المستأجر.
- [ ] Responses العامة وبيانات السؤال قبل اكتمال الإجابة لا تكشف الإجابة الصحيحة أو score غير المستحق.

أي فشل في العزل، أو كشف الإجابة الصحيحة، أو فقد الاستعادة بعد F5، أو فشل migration/backup/SMTP/S3 يمنع إعطاء رابط الـpilot حتى يُشخّص كتراجع حقيقي أو مشكلة بنية تحتية.

## قبول الـpilot

- لا تُدعَ مجموعة الطلاب قبل نجاح الرحلة السابقة على النطاق الإنتاجي نفسه.
- استخدم 3–5 معلمين كحد أولي، وسجّل لكل مشكلة الوقت و`X-Request-Id` والخطوات من دون نسخ tokens أو كلمات مرور.
- راقب health وbackup وOutbox يوميًا في أول أسبوع حتى مع وجود timer.
- عند أي خلل في العزل أو كشف إجابة صحيحة أو فقد بيانات، أوقف التوسع واتبع runbook الحوادث قبل استئناف الاستخدام.

## ما يحتاجه المشغل من الجهة

- Domain وDNS وشهادات TLS.
- PostgreSQL وS3-compatible bucket وSMTP credentials من Secret store.
- QuestPDF license selection وخط عربي متاح على Linux.
- Age recipient ونسخة آمنة من private identity للاستعادة.
- حساب Vercel وبيئة GitHub `production` وأسرار النشر الموضحة في `docs/deployment.md`.
